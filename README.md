# База данных «Пункты ГНСС п. Импилахти»

## 1. Назначение

База данных создана 21.06.2026 в рамках полевой геодезической практики. Цель — объединение информации о пунктах местной геодезической сети п. Импилахти в единую систему знаний. ГНСС-наблюдения на пунктах выполнялись в режиме статика.

База требует ежегодного обслуживания для поддержания актуальности сведений о пунктах местной сети.

## 2. О базе

База представляет собой файл GeoJSON с внутренней системой координат EPSG:4326 (WGS 84). Координаты точек представлены двумя форматами:

- геометрия — мультиточка с координатами Lat/Lon в десятичных градусах;
- плоские прямоугольные координаты в местной системе координат.

Файл содержит следующие поля:

- fid — Int — уникальный идентификатор внутри GeoJSON;
- idx_itrf — Str(4) — уникальное четырёхзначное имя пункта на латинице, заданное в соответствии с ITRF;
- full_name — Str — полное имя пункта;
- H_local — Float/Real — высота пункта в местной системе, в метрах;
- X_local — Float/Real — координата X в местной системе, в метрах;
- Y_local — Float/Real — координата Y в местной системе, в метрах;
- sign_type — Str — тип знака пункта (пирамида, сигнал, тур);
- center_type — Str — тип центра пункта (грунтовый, арматура);
- h_above_ground — Float/Real — высота знака над (под) землёй, в метрах. Отрицательное значение означает, что знак лежит ниже уровня земли;
- last_observed_year — Int — год обновления информации о точке, в формате yyyy;
- built_year — Int — год закладки точки, в формате yyyy;
- has_trench — Boolean — True/False, наличие окопки;
- photo_path — Str — путь к фото-превью точки;
- note — Str — примечание.

## 3. Требования

- QGIS версии не ниже 3.40.1.
- Дополнительные библиотеки и плагины не требуются.
- Для подгрузки базовой карты OSM Standard необходимо подключение к Интернету.

## 4. Заполнение базы данных

### 4.1. Запись информации нового пункта

1. Загрузите фотографии пункта в корневую папку, назвав папку пункта в соответствии с четырёхбуквенным именем как в системе ITRF:

```text
ГНСС_Импилахти/Привязка/{idx_itrf}/*.png
```

2. Откройте проект `project.qgz` в QGIS.

3. Включите панель «Дополнительные инструменты оцифровки»:

```text
Вид -> Панели инструментов -> Дополнительные инструменты оцифровки
```

4. Выберите слой «Пункты», включите режим редактирования, затем «Добавить точечный объект».

5. На панели «Дополнительные инструменты оцифровки» нажмите кнопку «Включить дополнительные функции оцифровки».

6. В открывшемся меню введите долготу и широту в десятичном формате.

7. Заполните атрибутивную таблицу в соответствии с назначениями полей (см. п. 2).

### 4.2. Обновление информации для существующего пункта

1. Откройте проект `project.qgz` в QGIS и выберите активным слой «Пункты».

2. Включите режим редактирования слоя.

3. Обновите координаты и высоты пунктов, загрузите новые фотографии в соответствии с п. 4.1.1.

4. Обновите поле `last_observed_year`.

## 5. Использование базы данных

1. Откройте проект `project.qgz` в QGIS и выберите активным слой «Пункты».

2. Убедитесь в наличии соединения с Интернетом для подгрузки базовой карты OSM Standard.

3. На верхней панели выберите инструмент «Определить объекты» и нажмите левой кнопкой мыши на определяемый пункт. Должна открыться панель «Результат определения» с атрибутивной информацией.

4. Для просмотра галереи фотографий пункта нажмите тем же инструментом правой кнопкой мыши на пункт и выберите «Открыть галерею фото». В стандартном браузере откроется локальная страница с галереей фотографий.

## 6. Работа с репозиторием через upstream

### 6.1. Что такое upstream

Upstream — это исходный (оригинальный) репозиторий, от которого сделан форк. В контексте этого проекта upstream — репозиторий:

```bash
https://github.com/TovarishchF/impilahti_database.git
```

Студенты работают не напрямую с оригиналом, а через свой форк. Это позволяет:

- свободно вносить изменения, не боясь сломать основной репозиторий;
- получать свежие обновления из оригинала;
- предлагать свои изменения через Pull Request.

### 6.2. Пошаговая инструкция для студентов

**Шаг 1. Сделайте форк репозитория**

На странице `https://github.com/TovarishchF/impilahti_database` нажмите кнопку **Fork** в правом верхнем углу. GitHub создаст копию репозитория в вашем аккаунте.

**Шаг 2. Клонируйте свой форк**

```bash
git clone https://github.com/ваш_логин/impilahti_database.git
cd impilahti_database
```

**Шаг 3. Добавьте upstream**

```bash
git remote add upstream https://github.com/TovarishchF/impilahti_database.git
```

Проверьте, что remote настроены правильно:

```bash
git remote -v
```

В выводе должно быть два remote: `origin` (ваш форк) и `upstream` (оригинал).

**Шаг 4. Синхронизируйте свой форк с upstream**

Перед началом работы получите последние изменения из оригинала:

```bash
git fetch upstream
git checkout main
git merge upstream/main
```

Или одной командой:

```bash
git pull upstream main
```

Отправьте обновления в свой форк:

```bash
git push origin main
```

**Шаг 5. Внесите изменения**

Создайте отдельную ветку для своей работы:

```bash
git checkout -b update-2027
```

Внесите новые данные в GeoJSON, обновите фотографии и документацию. Затем закоммитьте изменения:

```bash
git add .
git commit -m "Обновление базы данных за 2027 год"
```

**Шаг 6. Отправьте изменения в свой форк**

```bash
git push origin update-2027
```

**Шаг 7. Создайте Pull Request**

На странице вашего форка на GitHub появится предложение создать Pull Request. Нажмите **Compare & pull request**, убедитесь, что изменения идут в `TovarishchF/impilahti_database:main`, и создайте запрос.

### 6.3. Если вы работаете без форка

Если вы клонировали оригинальный репозиторий напрямую:

```bash
git clone https://github.com/TovarishchF/impilahti_database.git
```

то `origin` уже указывает на оригинал, и отдельный `upstream` не нужен. Однако в этом случае у вас не будет прав на push, поэтому для отправки изменений всё равно потребуется форк или доступ к репозиторию.
